# A warmer layout with clear priorities

The later [visual identity](visual-identity.md) refines the colors, type, mark,
and surface roles while retaining the page priorities below.

This revision follows the style audit. The earlier reduction left too many
different tasks at the same visual weight. It also made the learning page a
long sequence of similar text sections before a person reached practice.

## Page priorities

| Page | First priority | Supporting content |
| --- | --- | --- |
| Home | One distinct panel for checking a message | Recovery and learning stay as simpler task rows below. |
| Check | A focused input area and clear submit action | Screenshot review, privacy, errors, and limits stay beside the relevant step. |
| Result | The result, protective steps, and relevant limits | Actions share one reading surface; each action remains a numbered row. Optional explanations stay folded. |
| Recovery | The urgent payment step | Topic rows lead to the full plan; open topics gain a subtle reading background. Helpline choices stay separate. |
| Learn | Read the signs and try a message | Signs and practice sit side by side on desktop. The longer guide follows below. Phones use one column. |
| About | Capabilities, limits, and privacy together | One shared band groups the three facts; longer definitions remain plain reading rows. |

Warm sage surfaces, moderate serif headings, and modest corner rounding return
where they help group an activity or establish priority. The input form has a
very light shadow. Other reading sections use spacing and rules. There are no
decorative icon tiles, repeated card grids, or oversized three-line hero titles.

The learning headings now follow a clear outline: page title, the signs section,
then each individual sign. The practice is a distinct activity, with its message
and answer controls kept together. It does not turn every warning sign into a
separate panel.

The shared content width is 1120 px. Related text uses tighter spacing; transitions
between tasks use more space. The desktop learning layout stacks below 900 px.
Phone controls keep their large targets and text remains readable when enlarged.

This is a presentation change. Detection, reference review status, screenshot
limits, sharing, stored data, and practice behavior are unchanged.

The code and existing browser checks cover the page flows, keyboard use, phone
reflow, enlarged text, printing, and real screenshot input. Observed usability
with older adults remains separate evidence.
