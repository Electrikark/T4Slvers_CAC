# Purposeful interface styling

The later [balanced layout](balanced-layout.md) revises the degree of reduction
while retaining this audit’s emphasis on purpose and clarity. The table below
records the earlier pass.

The style audit covers Home, Check, Recovery, Learn, About, and the checker result.
Visual elements should help a person choose a task, read evidence, understand a
limit, or take a protective step.

| Pattern | Finding | Change |
| --- | --- | --- |
| Gradients | None in the served interface | No gradient styling added. |
| Large hero | A forced three-line title and repeated pause advice delayed the task links | Use one moderate heading and a short task introduction. |
| Decorative icons | Home icon tiles, pause glyph, lesson badges, a privacy dot, and repeated forward arrows added little information | Remove them. Keep the brand mark and result-state symbols. |
| Repeated card grids | Home tasks, learning signs, About facts, and result actions shared the same box treatment despite different jobs | Use task rows, reading sections, a label-and-text layout, and a native ordered action list. |
| Excess rounded panels | Nested recovery and trusted-help boxes made background look as important as urgent steps | Use separators and indentation. Keep modest corners on inputs, controls, warning panels, and distinct helpline services. |
| Shadows | The pause panel and form used depth as decoration; the active navigation and evidence underline also used shadows | Remove decorative depth. Use a real border for active navigation and a real underline for marked evidence. |
| Oversized headings | Desktop home title reached 81 px; page headings reached 59.4 px | Limit main page headings to 40.5 px on desktop and 34.2 px on phones. Result headings are at most 36 px. |

The warning tint, strong result border, uncertainty note, visible protective
actions, evidence highlights, selected choices, keyboard focus, and large control
targets remain. Their styling conveys state or supports use. Side-by-side input
choices and helpline services remain where their separate choices are useful.

The audit changes presentation and home introduction text. It does not change
the detection engine, screenshot review, approvals, stored records, sharing,
or the help and learning data.

Validation uses the existing code and browser checks, phone and desktop images,
and a read of computed styles on the five pages. Visual review is separate from
observed usability testing with older adults.
